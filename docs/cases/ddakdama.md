# 딱담아 · 장보기 추천을 실제 구매 준비로 연결하기

[포트폴리오 홈](../../README.md) · [이력서](../resume.ko.md)

## 누구의 어떤 문제에서 시작했나

장보기 목록은 정했지만 쇼핑몰에서 상품을 하나씩 다시 검색하고, 용량·가격을 비교하고, 장바구니를 채워야 하는 사람을 위한 제품입니다. AI의 추천과 실제 구매 준비 사이에 남은 반복 작업을 줄이는 것이 출발점입니다.

## 어떤 변화를 만들고 싶었나

목록을 한 번 입력하고 후보를 검토하면, 사용자가 사려던 상품과 수량으로 구매 준비를 이어갈 수 있게 하려 했습니다.

이는 제품 기획에서 설정한 문제와 해결 가설입니다. 사용자 인터뷰나 측정된 개선 효과로 제시하는 내용은 아닙니다.

![딱담아 상품 비교](https://raw.githubusercontent.com/Artemis-ignis/Artemis-ignis/main/docs/assets/pm-portfolio/ddakdama-compare.jpg)

## 제품 경험을 어떻게 구성했나

**목록 입력 → 후보 비교 → 담기 전 확인 → 장바구니 전달 → 결과 검토**

상품명·규격·포장 단위·구매 수량을 분리했습니다. ‘두 개’라는 요청을 2개 묶음과 혼동하면 반복 작업을 줄이려던 제품이 잘못된 구매를 만들 수 있기 때문입니다.

## 구현 과정에서 무엇을 판단했나

정확한 후보는 자동 선택 대상으로 두되, 애매한 후보는 사람이 검토하도록 했습니다. 일부 상품에 문제가 생기면 확인된 항목과 재확인 항목을 나누고 다음 행동을 안내했습니다.

[사용자 과업 → 요구사항 → 범위 판단 → 검증 계획 읽기](ddakdama-brief.md)

## 내가 맡은 일

문제 정의, 사용자 흐름, 수량 처리와 완료 기준, 실패 후 복구 동선을 정하고 AI 도구를 활용해 구현·회귀 검증을 진행했습니다.

## 다음에 무엇을 검증할 것인가

사용자가 직접 준비한 목록으로 기존 방식과 제품 사용 과정을 비교하려 합니다. 구매 준비 시간과 전달 완료율을 살피고, 잘못된 상품·수량 전달 및 후보 재선택 이유를 함께 기록할 계획입니다. 아직 측정된 고객 수·매출·전환 개선 수치는 없습니다.

## 이 경험에서 배운 것

편리함은 자동화한 단계의 개수만으로 설명되지 않았습니다. 사용자가 원한 상품인지 확신하고, 문제가 생겨도 이어갈 수 있게 만드는 판단이 필요했습니다.
