# 박준성

## AI Product Manager · Product Builder

사용자 문제를 정의하고, 가장 작은 검증 가능한 제품을 설계하고, 실제 파일·브라우저·사용자 흐름으로 품질을 확인하는 신입·주니어 PM/PO입니다.

[GitHub 프로필](https://github.com/Artemis-ignis) · [English resume](resume.en.md)

## 지원 방향

- 서비스 기획 / Product Manager / Product Owner
- AI-native 제품, SaaS, 커머스·콘텐츠·게임 도메인
- 문제 정의, 요구사항 구조화, 사용자 흐름, 우선순위, 제품 QA가 필요한 초기 제품팀

## 핵심 요약

- 메타체인에서 블록체인 게임 콘텐츠 기획·시장 조사·제안서·마케팅을 경험했습니다.
- 현재 Clunk 개인 제품 프로젝트에서 제품 방향, 요구사항, 품질 기준, 브라우저 흐름과 실제 파일 검증을 직접 설계·검수하고 있습니다.
- AI 도구가 만든 결과를 그대로 성과로 포장하지 않고, 자동 검사·실제 렌더·사람의 품질 판단을 구분해 기록합니다.
- 확인된 사실, 제품 가설, 입사 후 계획을 분리해 팀의 다음 의사결정을 돕는 방식을 지향합니다.

## 대표 제품 사례

### Clunk · 제품 기획·검증 · 비공개 제품 사례

- 문제: 게임 제작자가 생성된 에셋을 실제 프로젝트에 사용해도 되는지 판단하려면 파일 규격·내용·품질 근거를 따로 확인해야 합니다.
- 역할: 생성 → 검사 → 마켓 탐색 → 다운로드·에이전트 연동 흐름의 제품 방향, 요구사항, 품질 기준을 설계했습니다.
- 검증: 실제 파일, 브라우저 화면, 자동 검사, 실제 렌더, 사람의 품질 판단을 별도 상태로 확인했습니다.
- 공개 범위: [라이브 제품](https://clunk.games)과 [clunk-mcp 공개 저장소](https://github.com/Artemis-ignis/clunk-mcp)에서 확인 가능한 자료만 공개합니다.

- 상품 정체성, 포장 단위, 요청 수량, 최종 사용자 승인을 분리해 오류 경계를 명확히 했습니다.

## PM 작업 방식

문제 관찰 → 문제 정의 → 가설 수립 → MVP 범위 설정 → 구현·프로토타이핑 → 실제 근거로 검증 → 학습과 다음 우선순위 결정

문제 정의, JTBD, 사용자 여정, 요구사항, 수용 기준, 실패 경계, 출시 체크리스트를 제품 문서의 핵심으로 봅니다.

## 기술·도구

외부 고객 수, 매출, 전환율, PMF, 시간 절감처럼 현재 확인하지 못한 수치는 성과로 주장하지 않습니다. 실제 수행, 제품 가설, 입사 후 계획을 각기 다른 시제로 작성합니다.
