## 01 · Clunk · 주간 랭킹 게임 운영

모든 플레이어에게 그날 같은 블록을 제공하고, 세 가지 게임의 주간 최고 기록을 비교하는 웹 게임입니다. 탑 쌓기·퍼즐·스매시를 한국어와 영어로 운영합니다.

<a href="https://clunk.games"><img src="https://raw.githubusercontent.com/Artemis-ignis/Artemis-ignis/main/docs/assets/pm-portfolio/clunk-games-home-20260927.jpg" width="100%" alt="Clunk 주간 랭킹 게임 홈 화면, 2026년 9월 27일 캡처" /></a>

**제품 기준과 운영 대응**
- 모든 플레이어에게 동일한 블록 순서를 제공하고, 퍼즐 점수는 서버에서 입력 기록을 재생해 다시 계산합니다. 비정상적으로 높은 기록은 검토 전 순위표에 올리지 않습니다.
- 한 IP에서 여러 계정으로 랭킹전을 치른 사례를 확인한 뒤, IP별 가입 한도를 시간당 5개·하루 8개로 제한했습니다. 사이트 플레이 수를 순수 외부 사용자 수로 보고하지 않습니다.
- 9월 25일 주간 기록을 매번 다시 읽던 쿼리가 무료 DB 읽기 한도를 넘겨 약 6시간 중단됐습니다. 최고 기록 테이블과 하루 단위 순위 저장으로 바꾼 뒤 기존 순위 110건을 모두 대조했습니다.

**내가 맡은 일** · 게임 규칙·랭킹 정책, 악용 대응 기준, 장애 대응, 복구 결과 검수. 구현·자동 점검·배포에는 AI 도구를 사용했습니다.

[현재 라이브 화면 →](https://clunk.games) · [상세 사례 →](docs/cases/clunk.md) · Clunk 소스 저장소는 비공개입니다.

## 02 · 딱담아 · ChatGPT 쇼핑 목록을 쿠팡 장바구니로

사용자가 ChatGPT에서 만든 쇼핑 목록을 검토하고, Chrome 확장 프로그램에서 상품 후보를 확인한 뒤 승인한 항목만 쿠팡 장바구니로 전달합니다. 결제와 비밀번호는 다루지 않습니다.

<img src="https://raw.githubusercontent.com/Artemis-ignis/Artemis-ignis/main/docs/assets/pm-portfolio/ddakdama-flow.jpg" width="100%" alt="딱담아 목록·상품 확인·장바구니 전달 흐름" />

**정확성과 복구 기준**
- ‘100mg 240정’ 한 통을 240개로 읽는 오류를 테스트에서 찾아 수량 판단을 규칙 코드로 옮겼습니다.
- 가격을 확인하지 못한 상품은 자동으로 담지 않고, 일부 항목만 실패하면 재확인할 상품을 따로 보여 줍니다.
- 단위 테스트 94개, Playwright E2E, 실제 쿠팡 상품 5종, ChatGPT 앱 연결을 확인했습니다. 실사용자 테스트와 구매 시간 개선은 아직 측정하지 않았습니다.

## 04 · REEZEN · 진행 중인 이커머스 팀 프로젝트

처음에는 Gen Z가 온라인에서 옷을 살 때 핏·사이즈를 확신하지 못해 구매를 미룬다는 가설로 시작했습니다. 팀 인터뷰 5건의 10월 2일 요약은 구매 보류 이유로 당장 필요 없음·계절·예상 착용 빈도·가격 대비 품질을 들었고, ‘어울릴지 몰라서’를 이유로 든 사람은 0/5였습니다. 같은 요약에서는 상품 발견은 괜찮았고 동일 상품의 가격 비교에 시간이 걸렸다고 정리했습니다.

9월 30일 인터뷰 분석 문서는 ‘확인 단계에서 막힘’을 5/5로 기술합니다. 두 정리의 질문·집계 기준이 달라 보여 문제 정의를 확정하지 않고, 차이를 다시 확인할 과제로 남겼습니다. 인터뷰는 다섯 명의 탐색 결과이지 시장 전체를 대표하는 검증이 아닙니다.

**내가 맡은 일** · Nemotron 한국어 가상 페르소나 데이터셋을 팀에 제안하고 60개 LLM 응답으로 설문 흐름을 사전 점검했습니다. 이 응답은 실제 사용자 검증이 아닙니다. 설문을 13개 섹션에서 7개로, 분기를 5개에서 1개로 줄이는 개편안을 제시했고 최종 설문에 반영됐습니다. 팀 인터뷰 5건 중 1건을 직접 진행하고 5건을 분석했으며, 9월 30일에는 반복되는 쇼핑 문제부터 확인하자는 개인 제안을 작성했습니다.

10월 2일 멘토링은 목표 지표 하나와 좁은 문제·카테고리를 정하라고 제안했지만, 이는 팀의 결정이 아닙니다. 설문 유효 표본 수는 문서마다 달라 확인 전까지 싣지 않았습니다.
