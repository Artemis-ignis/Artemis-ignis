# 픽토리 · 쌓인 사진을 쉽게 찾고 정리하기

[포트폴리오 홈](../../README.md) · [이력서](../resume.ko.md)

## 누구의 어떤 문제에서 시작했나

사진이 많이 쌓여 원하는 컷을 찾기 어렵고, 일일이 살펴보며 분류하는 일을 미루는 사람을 위한 제품입니다. 사진을 모아 두는 것에서 다시 찾고 활용하는 것으로 이어지게 하고 싶었습니다.

## 어떤 변화를 만들고 싶었나

사진을 선택하면 분류된 묶음을 검토하고 원하는 사진을 보관할 수 있도록, 사용자가 직접 탐색하고 정리해야 하는 부담을 줄이려 했습니다.

이는 제품 기획에서 설정한 문제와 해결 가설입니다. 사용자 인터뷰나 측정된 개선 효과로 제시하는 내용은 아닙니다.

## 제품 경험을 어떻게 구성했나

**정리 목적 선택 → 사진 선택 → 분류별·날짜별 결과 검토 → 정리·보관**

사용자가 결과를 읽고 선택할 수 있도록 홈·정리·보관 화면과 분류별·날짜별 탐색을 구성했습니다. 분류가 끝나는 시점보다 사용자가 원하는 사진을 찾고 남기는 순간을 제품 흐름의 끝으로 보았습니다.

## 구현 과정에서 무엇을 판단했나

민감·확인 필요 후보는 실제 썸네일 대신 대체 이미지를 쓰도록 했습니다. 사용량·광고 보상·구독은 확인된 이벤트와 서버 상태를 기준으로 적용하도록 설계했습니다.

## 내가 맡은 일

사용자 여정·정보 구조·정리 흐름, 개인정보 처리와 사용 권한 기준을 정하고 AI 도구를 활용해 구현·검수했습니다.

## 현재 보여줄 수 있는 결과

홈·정리·보관 화면, 분류·사용량·권한 연결부를 구현했습니다. 실제 토스 단말에서의 사진 권한·광고·결제 검증은 출시 전 과제입니다.

[공개 저장소](https://github.com/Artemis-ignis/pictory-apps-in-toss)

## 다음에 무엇을 검증할 것인가

원하는 사진을 찾아 보관하는 과업을 관찰하고, 탐색 단계·분류 수정 이유·완료 여부를 기록하려 합니다. 민감 이미지 노출과 데이터 삭제 이해도도 함께 확인할 계획입니다. 아직 측정된 고객 수·매출·전환 개선 수치는 없습니다.

## 이 경험에서 배운 것

분류 결과를 많이 만드는 것보다 사용자가 이해할 수 있는 묶음과 다음 행동을 제공하는 일이 중요했습니다. 개인정보와 비용을 다루는 정책도 이 경험이 지속되는 조건으로 보았습니다.
